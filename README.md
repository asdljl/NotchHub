# NotchHub

Windows 上的「灵动岛」——贴在屏幕顶部中央，用来随手管理**计时器**和**待办清单**。空闲时收成一枚小圆点，一旦有计时器在跑或还有未完成的待办，就自动展开成刘海；鼠标移上去再展开成完整面板。也可以在设置里锁定成整条刘海。灵感来自 macOS 上的 NotchNook。

## 功能

### 计时器（支持多个并行）

- 「新建计时器」按钮新建，最多同时跑 12 个，每个可单独命名
- 时 / 分 / 秒三列滚轮：滚轮滚动或按住上下拖动都能调，松手吸附到最近一格，选中项蓝色高亮，带 h / m / s 单位
- 快捷预设：1 / 5 / 10 / 25 分钟
- 列表里每行显示环形剩余进度、大号倒计时、暂停/继续、关闭
- 结束时三音阶提示音 + 系统通知 + 该行转绿
- 收起时，胶囊左侧是一枚环形进度，随剩余时间收缩；中间是倒计时数字
- **完成提示只显示 8 秒**：期间播完成动画（数字退场、绿色圆环、六道火花、对勾逐笔画出、标题滑入），随后自动把收起态交还给仍在跑的计时器；展开面板即视为已读，立刻归位
- 多个并行时角标显示数量；完成提示期间角标显示「还有几个在跑」，一枚对勾不会遮住其它计时器
- 列表顶部有「清除已完成」按钮，完成的记录不会一直占着 12 个名额

### 待办清单（项目 → 子待办）

- **项目**：右上角「项目」新建一个大项目，每个项目下可以放任意多个子待办。项目卡片有独立色点、完成进度条（`已完成/总数`）、折叠、重命名和删除
- 添加子待办有两种入口：顶部快速添加行（右侧下拉选目标项目，默认「独立」），或每张项目卡片底部的「添加子待办」（回车可连续添加）。输入后点左侧「+」、顶部右侧「添加」或内联行右侧「完成」都能提交，不必非得按回车；「完成」会先保存当前输入再收起输入行，`Esc` 则取消本次输入
- **删除项目不会删掉工作**：子待办自动退回「独立待办」分组；删除前有确认条
- **三个筛选视图**（顶部「未完成 / 今天 / 明天」，带数量角标），每个视图都按项目卡片分组：
  - `未完成`：所有项目 + 未完成的子待办，新加的排在最前；已完成项收在卡片内可折叠的「已完成 N」里
  - `今天`：计划日为今天**或已逾期**的子待办（逾期显示红色「逾期 N 天」）
  - `明天`：计划日为明天的子待办
  - 从今天 / 明天视图添加子待办时，会自动把该天 `23:59:59` 设为计划完成时间
- **编辑已创建的子待办**：
  - 直接点任务文字进入**行内改名**，`Enter` / 失焦保存，`Esc` 取消，空名字不会覆盖原文；已完成的任务同样能改
  - 点右侧**铅笔**（或「+ 计划」、铃铛）打开「编辑任务」弹层，一次修改**名称、所属项目、计划完成时间、提醒**四项；改名只更新 `text`，id、星标、创建时间和完成状态都保留
  - 计划完成日**精确到时分秒**：「今天 / 明天 / 清除」+ **shadcn/ui `Calendar`** 选日期（在弹层内内联展开，中文月份与星期）+ `Input[type=time][step=1]` 选时刻，存为 `YYYY-MM-DDTHH:mm:ss` 本地时间。列表徽标同步显示 `今天 09:30:45`；旧的纯日期存档仍可读，打开编辑器时补默认 `23:59:59`。不设日期时时刻输入禁用。不再用原生 `input[type=date]` / `datetime-local` —— 系统日期弹窗会被透明置顶小窗裁切
  - 提醒有四种：**无 / 每日 / 定时 / 计划完成时**。「计划完成时」不存独立时间戳，直接跟随任务的计划完成时刻；改计划时间会自动重新计时，没设计划日时禁止保存。定时提醒仍是「日历选日期 + 时间输入」。计划日 ≠ 提醒时间：没显式设计划日时，若设了定时提醒，会按提醒的日期归入今天 / 明天
  - 只改名称/项目不会重放已响过的提醒，也不会清掉待触发的「稍后提醒」；只有真正改了提醒规则才重新开始计时
- 圆形勾选完成、星标置顶、已完成归档、提醒、稍后提醒都保持原有行为；未完成数量实时同步到胶囊角标（统计所有项目下的子待办）

### 设置

- **触发方式**（交互）：`悬浮展开` / `点击展开` / `悬浮或点击`，下拉选择，改完立刻生效
- **圆点模式**（外观）：开关，**默认开启**。开启时收起态按活动状态在「26px 圆点 ↔ 整条刘海」之间自动切换；关闭后始终显示整条刘海，不受活动状态影响。「恢复默认」会回到开启状态
- **透明度**（外观）：72% – 100%，控制岛背景的通透程度
- **刘海宽度**：160 – 300 px，收起态胶囊的宽度（圆点模式下暂不生效）
- **刘海高度**：26 – 48 px，胶囊高度，底部圆角自动跟随（圆点模式下暂不生效）
- **面板宽度**：320 – 560 px
- **面板高度**：360 – 680 px

分「交互」与「外观」两组。数字项左侧标签、右侧输入框，回车或失焦后生效；原生窗口会跟着变大变小并重新贴顶居中，鼠标热区同步更新。

### 收起态的形态规则

圆点模式开启时，收起态不是固定的，而是跟着「正在进行的事」变形：

| 正在进行的事 | 形态 | 上面显示什么 |
| --- | --- | --- |
| 都没有 | 26px 圆点 | 白色慢波涟漪 |
| 只有计时器在跑 | 刘海 | 蓝色进度环 + 剩余时间；多个计时器时蓝色角标显示数量 |
| 只有待办未完成 | 刘海 | 时钟 + 绿色小点 + 绿色待办数 |
| **计时器与待办同时存在** | 刘海 | **主视觉归计时器**（进度环 + 剩余时间，时间更敏感），待办用右侧绿色角标计数；多个计时器再加一个蓝色角标。蓝 = 计时、绿 = 待办，和圆点状态同一套配色 |
| 计时结束 / 待办完成或删除，且无其它活动 | 收成圆点 | 结束提示在圆点上播绿色对勾，8 秒后回到空闲白点 |

判定只看「正在运行的计时器」和「未完成的待办」两项。暂停的计时器、8 秒的完成提示、响过的待办提醒都不算活动状态，不会把刘海撑着；已完成的待办也不算。手动关掉「圆点模式」则始终是刘海，行为与旧版一致。

形态变化走 `.island` 原有的 320ms `--ease-shell` 宽高/圆角过渡；切换瞬间给新内容加 260ms 淡入（`shape-in`），由 `data-morphing` 标记仅在变形的 300ms 内生效，不干扰展开/收起那套交叉淡入淡出。原生热区同步跟随**有效形态**（`setDotMode(showDot)`）：圆点只有中心约 40×34px，刘海则整条可悬浮/点击。`prefers-reduced-motion` 下淡入禁用。

### 圆点的状态与动效

圆点靠颜色、光晕、圆环和对勾表达状态，不显示文字。所有状态共享一套**从中心向外扩散的水波涟漪**：三层 1px 细环从 8px 长到 44px，各错开 1/3 周期，每圈在半径走完约 6 成时就淡出，所以画面里始终只有一道主波在前行，不会变成静态靶心。动画改的是 `width/height` 而不是 `transform: scale()`，波纹始终是一根发丝细线。

| 场景 | 静态表现 | 动效 |
| --- | --- | --- |
| 空闲（默认） | 哑光白核心 + 极淡细环 | 3.2s 白色慢波 + 核心轻微呼吸 |
| 悬停 | 核心放大提亮、细环扩张、外壳描边变亮 | 波峰提亮到 0.48，节奏不变（避免鼠标进入时波纹跳帧） |
| 按下 / 展开瞬间 | 核心收缩、细环收紧、外壳泛蓝 | 额外一圈 560ms 的点击波；展开时核心再放大一次并随圆点淡出 |
| 有未完成待办 | 绿色核心 + 绿色柔光 | 2.6s 绿色波 + 核心呼吸 |
| 计时进行中 | 蓝色核心 + 剩余时间进度环 | 2.4s 蓝色波、核心心跳、进度环上一道 2.4s 巡回扫描高光 |
| 待办提醒 | 琥珀核心 + 光晕 | 1.7s 急促琥珀波 + 核心闪烁 + 声波环，波扩散到 48px |
| 计时结束（8 秒内） | 绿色对勾、核心隐去，右下角蓝色角标显示仍在跑的计时器数 | 进入状态时播一次 1.05s 绿色扩散波，之后自动让位给进度环 / 待办 / 空闲 |

状态切换只改 `--wave-rgb / --wave-alpha / --wave-cycle / --wave-reach` 四个变量，颜色带 240ms 过渡，所以换状态时波纹是渐变而不是跳变。颜色、尺寸变化都走 200–280ms 过渡，展开/收起沿用胶囊那套交叉淡入淡出；`prefers-reduced-motion` 下全部波浪层直接隐藏，只保留静态结果。

为了让涟漪能画到圆点外面，收起态外壳是 `overflow: visible`。代价是收起时 380px 宽的面板内容可能溢出到正在收缩的 26px 圆点两侧 —— 所以 `.panel` 用 `visibility: hidden` 在收起瞬间立刻消失（0s 切换），而 `opacity` 仍照常淡出；展开方向保持 `opacity` 延迟 190ms 的交叉淡入不变。

### 外壳

- 收起态无活动时为 26px 圆点、有活动时自动变刘海，顶部与屏幕边缘严丝合缝
- 圆点模式下鼠标热区只有圆点周围约 40×34px，其余原胶囊区域保持穿透
- 三种唤醒方式可选：悬浮即展开、仅点击展开、两者皆可
- 鼠标离开 320ms 后自动收起，`Esc` 立即收起；但行内改名、内联添加行或「编辑任务」弹层打开时，`Esc` 只退出当前输入，不会收起岛
- 收起时窗口鼠标穿透，不遮挡下方任何窗口
- 系统托盘菜单：显示 / 隐藏、退出

## 技术栈

| 层 | 选型 |
| --- | --- |
| 外壳 | Tauri 2（Rust） |
| 界面 | React 19 + TypeScript + Vite 8 |
| 控件 | **shadcn/ui**（Radix UI + CVA + lucide 图标），源码落在 `src/components/ui/` |
| 样式 | **Tailwind CSS v4**（theme + utilities）+ 手写 CSS 分层共存 |
| 持久化 | localStorage（WebView2 本地存储，跨重启保留） |
| 通知 | tauri-plugin-notification |
| 更新 | GitHub Releases API（Rust 侧 reqwest：检查 → 流式下载 → 交给 NSIS 静默安装） |

面板里的按钮、输入框、下拉、开关、标签、徽标、进度条、复选框、卡片、分段标签、弹层与日历都来自 shadcn/ui；`components.json` 已配好，可以继续用 `npx shadcn@latest add <组件>` 扩展。岛外壳、圆点涟漪、胶囊、滚轮等定制视觉仍由手写 CSS 负责。

日历是官方 `calendar` 组件（`react-day-picker` v9 + 中文本地化），按岛内尺寸把单元格从 2rem 收到 26px，样式全用 Tailwind 类，不引入 rdp 自带 CSS。因为它是按需展开的，组件与语言包用 `React.lazy` 拆成独立 chunk，主包不受影响；`vite.config.ts` 的 `optimizeDeps.include` 把该依赖纳入首次预构建，避免运行时重新优化时批量替换缓存目录。日历展开时底部「取消 / 保存」固定在弹层底部，`Esc` 先收日历、再收弹层。

## 开发

```bash
npm install
npm run tauri dev     # 开发模式，热更新
npm run tauri build   # 打包安装程序
```

需要 Rust 工具链、Node 18+ 与 WebView2 运行时（Windows 10/11 一般已自带）。

## 在线更新

应用内置「检查更新 → 下载 → 安装重启」的完整闭环，数据源是 GitHub Releases。设置面板底部有一张「更新」卡片，托盘菜单里也有一个「检查更新」入口。

### 工作方式

1. 当前版本来自打包元数据（`tauri.conf.json` 的 `version`），不读 `package.json`，所以在 `tauri dev` 和安装后的程序里读到的是同一个值。
2. 启动 6 秒后静默查一次 `GET /repos/{owner}/{repo}/releases/latest`，有新版本时「设置」tab 上出现一个蓝点；点「检查更新」会立即重查。
3. 用 semver 比较 tag 与当前版本（`v1.2.0` 与 `1.2.0` 等价，预发布后缀也参与比较），远端更大才算有更新。
4. 挑安装包的顺序：`*-setup.exe`（NSIS）> 名字含 `nsis` 的 exe > 其它 exe > `*.msi`；`.sig`、`.zip`、异架构（arm64 / x64）资产会被跳过。
5. 下载流式写入 `%LOCALAPPDATA%\com.notchhub.desktop\cache\updates\`，每 120ms 通过 `updater://progress` 事件回报字节数、百分比与速度；结束后校验 Content-Length 和 GitHub 提供的 `digest`（`sha256:...`，有则校验）。
6. 「安装并重启」把安装包交给 `cmd`：先等 2 秒让当前进程退出，再执行 `setup.exe /S` 静默安装（MSI 则 `msiexec /i … /qb`），装完 `del` 掉安装包并重新拉起程序。

### 发布新版本

1. 改 `src-tauri/tauri.conf.json` 的 `version`（建议 `Cargo.toml`、`package.json` 一起改），提交。
2. `git tag v0.2.0 && git push origin v0.2.0`。仓库里的 `.github/workflows/release.yml` 会构建并生成**草稿** Release；也可以本地 `npm run tauri build` 后把安装包手动拖进 Release。
3. Release 必须是 **published** 状态——`/releases/latest` 不返回草稿和预发布版本。
4. 安装包名保持 Tauri 默认的 `NotchHub_<version>_x64-setup.exe`，挑包规则就不用额外配置。

### 配置

| 时机 | 变量 | 说明 |
| --- | --- | --- |
| 构建时 | `NOTCHHUB_UPDATE_REPO` | `owner/repo`，也接受完整 GitHub URL 或 `git@` 写法。默认 `qdy/NotchHub`。 |
| 构建时 | `NOTCHHUB_GITHUB_API` | API 根地址，默认 `https://api.github.com`，可指向 GitHub Enterprise 或镜像。 |
| 运行时 | `NOTCHHUB_GITHUB_TOKEN` | 匿名调用限 60 次/小时；私有仓库的资产下载也必须带 token。 |

`reqwest` 默认走系统代理并识别 `HTTPS_PROXY`，网络受限的环境不用改代码。例如：

```powershell
$env:NOTCHHUB_UPDATE_REPO="me/NotchHub"; npm run tauri build
```

### 开发与打包环境的差异

- `npm run dev`（纯浏览器）只有界面：「检查更新」会提示「浏览器预览中无法检查更新，请在桌面应用里使用」。
- `tauri dev`（debug 构建）能完整检查、下载，但**不会**自动安装：点「安装并重启」只会在资源管理器里定位到安装包，避免把 `target\debug` 里的调试程序替换成正式版。判定依据是 `cfg!(debug_assertions)`。
- 正式安装后一切照常。`nsis.installMode = currentUser`，安装到当前用户目录，静默升级不需要管理员权限。

### 失败时看到什么

每个错误都带机器可读的 `code` 和中文 `message`，原始原因放在 `detail` 里小字显示：`connect` / `timeout`（网络或代理）、`not_found`（仓库或 Release 不存在）、`rate_limit`、`server`、`no_asset`（该版本没提供 Windows 安装包）、`digest` / `size`（下载被截断或篡改）、`cancelled`、`no_download`、`io`。后台静默检查失败不会打断用户，等打开面板时才显示；下载失败会保留「重试」按钮，已下载完的安装包可以「重新安装」或「打开文件」手动处理。

## 架构要点

### shadcn/ui 与手写 CSS 如何共存

shadcn/ui 不是 npm 组件库，而是把官方组件源码放进仓库，因此它依赖 Tailwind 与 Radix。直接开 Tailwind 的 preflight 会重置掉 3000 多行调好的岛壳样式（圆点涟漪、形态动画、贴边阴影），所以 `src/shadcn.css` 只导入 `theme.css` 和 `utilities.css`，**跳过 preflight**，并声明层顺序：

```css
@layer theme, base, app, components, utilities;
```

`styles.css` 整体包在 `app` 层，Tailwind utilities 在它之上 —— shadcn 组件在自己拥有的元素上生效，而 `.island` / `.dot` / `.capsule` 这些定制规则完全不受影响。`base` 层只补一条 `border-style: solid`，否则没有 preflight 时 `border` 工具类不显示边框。

主题 token 定义在 `shadcn.css` 的 `:root`（`--primary` = `#0a84ff`、`--radius` = `0.625rem` 等），再通过 `@theme inline` 映射成 `--color-*`。项目原有的 `--accent` 是同一个蓝色，所以 shadcn 的中性 hover 色另用 `--sh-accent`，避免两种语义抢一个变量。

两个针对透明窗口的特殊处理：

- **Dialog 不能全屏遮罩**：`DialogOverlay` 是 `absolute inset-0` 而非 `fixed`，并且 `DialogPortal` 的 `container` 指向 `#notch-panel`。否则 380×480 的岛会变成把整个桌面压暗的全屏模态。
- **Radix Select 不接受空字符串 value**：「独立待办」这类空值统一映射成 `__standalone__` 常量，在读写数据时再转回 `null`。
- **编辑弹层的操作条不能放进滚动层**：`TaskSheet` 把内容装进内部 `.task-sheet__scroll`（`flex-1 min-h-0 overflow-y-auto`），「取消 / 保存」作为它的兄弟节点留在弹层底部。早先把操作条 `absolute bottom-0` 放在滚动容器内，固定层会盖住滚动区最后约 48px —— 提醒说明和日历最后一行都会被吃掉。内部间距按默认面板高度收紧过，未展开日历时一屏放得下，展开日历后按钮依然固定可见。时间输入还隐藏了原生 picker 图标：它弹出的系统选择器同样会被透明小窗裁切。

`prefers-reduced-motion` 下，除了原有动画，shadcn 的 portal 动画与按钮/输入过渡也一并禁用。

### 透明穿透窗口

窗口是 `transparent + decorations:false + alwaysOnTop + skipTaskbar`，固定在主显示器顶部居中。

收起态调用 `set_ignore_cursor_events(true)`，窗口完全穿透；此时前端收不到任何鼠标事件，所以由 Rust 侧起一个 45ms 的**全局光标轮询线程**（`watch_cursor`），用 Win32 `GetCursorPos` 判断指针是否进入热区，命中后把窗口切回可交互并发 `notch-open` 事件给前端。

离开检测同理：指针移出面板矩形超过 320ms 宽限即收起。`armed` 标志保证鼠标停在热区内不会反复开关。

### 三种唤醒方式

`hover` / `click` / `both` 存在 `AppState.trigger`（`AtomicU8`）里，轮询线程每帧读一次，所以切换是即时的，不需要重启。

点击模式有个绕不开的矛盾：收起态窗口是穿透的，点不到胶囊。做法是**只在指针位于热区内时把窗口切回可交互**，离开就立刻恢复穿透 —— 窗口其余透明区域仍然不吃点击。同时用 `GetAsyncKeyState(VK_LEFTBUTTON)` 做一次按下沿检测作为兜底：第一次点击可能被系统当成"激活窗口"而吞掉，Rust 侧的检测不会漏。

点击在三种模式下都生效。原因是 `armed` 会抑制"指针本来就在热区里"的重复展开 —— 比如按 `Esc` 收起后光标还停在刘海上，此时悬浮不会重新弹出，点一下才可以。

### 动态尺寸与热区

面板和胶囊的尺寸都可调，所以热区不再是常量，而是从 `AppState.panel` 派生：

```text
窗口宽 = 面板宽 + 40        胶囊（宽高可调）居中，作为收起态热区
窗口高 = 面板高 + 60        面板宽高即展开态热区
```

前端改设置时调用 `set_geometry(width, height, capsuleWidth, capsuleHeight)`，Rust 更新共享尺寸、`set_size` 调整窗口、重新贴顶居中，轮询线程下一帧自动使用新热区。胶囊圆角等于高度的一半，所以调高时它会自然变成更圆的药丸形。

### 外壳阴影不能超出窗口画布

`tauri.conf.json` 里 `shadow: false`，投影完全由 CSS 的 `.island` 绘制。但透明窗口只比面板左右各宽 20px、底部高 60px（`MARGIN_W/H`），**阴影一旦超出这块余量就会被窗口边界硬裁成直线**，在浅色背景上表现为面板周围一整圈浓黑矩形，展开时尤其明显。

所以展开/收起态的外阴影都收在 `blur + spread ≤ 20px` 以内（现在是 `0 10px 24px -14px` / `0 8px 20px -12px`，配合 1px 亮描边），在到达窗口边界前就衰减完。想加回"浮起感"应该先调大 `MARGIN_W/H`，而不是直接调大 `box-shadow`。圆点态阴影独立，因为圆点居中、四周余量有近 200px。

### 圆点模式与热区

`AppState.dot_mode`（`AtomicBool`，默认 `true`）由前端的 `set_dot_mode` 同步。轮询线程据此二选一：胶囊模式用可调的 `capsule_width/height` 当热区；圆点模式用固定的 `DOT_VISUAL_SIZE + DOT_HOT_PAD` 算一个居中的小方块。这样"只显示圆点"不只是视觉变化 —— 原来 240px 宽的胶囊区域确实不再吃鼠标。

`src/hooks/useSettings.ts` 的 `DOT_SIZE` 与 `lib.rs` 的 `DOT_VISUAL_SIZE` 必须保持一致：CSS 负责画镜头，Rust 负责画热区。外壳仍然是同一个 `.island`，只改宽高和 `border-radius: 50%`，所以展开/收起的尺寸动画、透明度设置和交叉淡入淡出都不需要另写一套。

### 展开动画的两个坑

胶囊长成面板是 180→380 宽、26→480 高的形变，位移很大，两个细节会让人误以为"抖动"：

- **缓动曲线不能换成强 ease-out。** `cubic-bezier(0.22,1,0.36,1)` 在第一帧就走完 15% 的高度，看起来像弹了一下。改用 `cubic-bezier(0.45,0,0.15,1)`（慢起→快中→缓收），首帧位移从 41px 降到 1px。
- **胶囊淡出和面板淡入要交叉。** 两者都在 0ms 起步会留下一个"什么都没有"的空窗；把胶囊的淡出推迟 30ms、面板推迟 190ms，才有内容接力。

另外收起（320ms）比展开（440ms）快，符合"离开比进入快"。

### Windows 11 圆角

Win11 的 DWM 会给所有顶层窗口加圆角，会把贴边的胶囊顶部削出两个缺口。`square_off_corners` 通过 `DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE, DWMWCP_DONOTROUND)` 关掉它。

### 滚轮的三种输入

滚轮同时接受鼠标滚轮、按住拖动和程序化滚动（预设按钮），三者共用一个 `scrollTop`，所以必须互相让路：

- 拖动时把 `scroll-snap-type` 临时改成 `none`，否则每拖过一格就被吸附弹回去；松手后再滚到最近的档位，并把 snap 还原。
- 拖动过程中 `onScroll` 会更新 `value`，而 `value` 变化本来会触发程序化 `scrollTo` —— 那个 effect 在检测到 `drag.current` 时直接返回，不跟指针抢。
- 用 `setPointerCapture` 保证拖出列宽也不丢事件。

### 滚轮的坑

滚轮用 `scroll-snap-type: y mandatory` 实现吸附。点击预设按钮会触发程序化 `scrollTo({behavior:'smooth'})`，而平滑滚动的中间位置会反过来触发 `onScroll`，把数值拖走。`Wheel.tsx` 用 `programmatic` 标志 + `scrollend` 事件屏蔽这段期间的滚动事件。

三列滚轮可能在同一帧内上报变化，因此 `TimerCreate` 的写入直接基于各列独立 state，避免互相覆盖。

### 提醒的三种反馈

待办到点不只是弹个通知。收起状态下胶囊会切到 `reminder` 模式：琥珀色铃铛摇摆两轮、声波环扩散、任务标题淡入，顶部还铺一层琥珀光晕；展开后待办列表里对应那行会闪三下并保持高亮 4 秒。

只有"当时面板是收起的"才把提醒塞进胶囊队列 —— 如果用户正开着面板，列表高亮和系统通知已经够了。打开面板 4 秒后队列清空，胶囊恢复显示时间。

### 提醒的触发

`useTodos` 每 20 秒轮询一次：每日提醒比对 `HH:mm` 并用日期做去重键；定时提醒比对时间戳并写 `once-fired` 标记；**「计划完成时」提醒**实时读 `todo.dueDate`，用 `due-fired:<完整计划值>` 做去重键 —— 所以改计划时刻会重新武装提醒，而改名、换项目不会重放。旧的只有日期的计划按当天 `23:59:59` 触发。应用关闭期间过期的「定时 / 计划完成时」提醒超过 24 小时后不再补发，避免重启时炸出一堆通知。

### 稍后提醒为什么不改原规则

「推迟 5 分钟」如果直接把 `kind` 改成一次性时间戳，第二天的每日提醒就没了。所以 `Reminder` 多了两个独立字段：`lastFiredAt`（用来决定是否展示稍后提醒条）和 `snoozeUntil`（这一次的延后时间）。

轮询时 `snoozeUntil` 优先于 `kind`/`value`；它响过之后清空自己，把控制权交回原规则。这样延后是"这一次"的行为，不会污染用户设置的重复规则。

### 项目是平行列表，不是嵌套数组

`notchhub.projects.v1` 存 `Project[]`，`notchhub.todos.v1` 仍是扁平的 `Todo[]`，每条多两个可空字段 `projectId` / `dueDate`（`YYYY-MM-DDTHH:mm:ss` 本地时刻，旧存档也接受 `YYYY-MM-DD`）。没有把子待办塞进项目对象里，三个原因：

- 提醒轮询、snooze、星标、收起态 `activeCount` 全都只遍历一层 `todos`，不用递归，也不用一个项目一个项目去汇总；
- 旧存档缺这两个字段时自然回落成 `null`，所有历史任务自动归到「独立待办」，不需要写迁移脚本；
- 删除项目只需把匹配的 `projectId` 置空，工作不会跟着消失。视图里只认 `projects` 中存在的 id，孤立 id 也按独立待办处理。

`lib/dates.ts` 负责所有计划时间的解析与归一化：`normalizeDue()` 校验本地时刻字符串（含不可能的日期）、`dueDay()` / `dueClock()` 拆两段、`parseDueAt()` 构造本地 `Date`（旧纯日期按 `23:59:59`）、`planSortKey()` 给出可比较的排序键。`effectiveDue()` 决定「今天 / 明天」：显式 `dueDate` 优先，否则若设了**定时**提醒就取提醒的日期；每日与「计划完成时」提醒没有独立日期，不参与。`dueBucket()` 把 `<= 今天` 的（含逾期）归到「今天」，`= 明天` 的归到「明天」。`TodoView` 按 `projects` 顺序 + 虚拟的「独立待办」分组出卡片，三个筛选只改变每组里可见的行，不改变分组本身。

「未完成」视图保持星标 + 创建时间倒序，保证新加的任务永远在最前；只有今天 / 明天视图才按完整计划时刻排序，同一天内也按时刻先后，让逾期项浮到顶部。

### 完成是事件，不是状态

早期版本把持久化里 `phase === "done"` 的记录直接映射成收起态的绿色对勾，优先级还高于运行中的计时器。结果多个计时器并行时，只要有一条完成记录没被手动删掉，圆点就永久停在对勾上，重启也一样，其它计时器的进度环全被盖住 —— 一次性事件被当成了持续状态。

现在 `App.tsx` 用一段**只在内存里**的 `finished` 列表表达「刚刚完成」：`onFinish` 压入 `{ id, title, at }`（面板本来开着就不压，那一行已经看得见），`FINISH_NOTICE_MS = 8000` 后按时间戳过滤自动过期；展开面板算已读，立即清空；不写 localStorage，所以 reload 不会复活旧提示。`Dot` / `Capsule` 只消费这段 notice，不再扫描持久化行。列表里的完成记录照旧保留，随时可重启或删除。

优先级仍是 `提醒 > 刚完成 > 运行中 > 有待办 > 空闲`，但完成只占 8 秒窗口，属于通知。这段时间内圆点右下角的蓝色角标报告仍在跑的计时器数（只剩一个也显示 `1`），胶囊则把角标让给运行数；列表顶部的「清除已完成」接的是 `useTimers.clearDone`，专门用来整理持久记录。

因为完成不再算活动状态：若此时没有其它计时器或待办，刘海会同时收成圆点，8 秒的绿色对勾就在这枚圆点上播放；若还有待办没做完，则保持刘海，由胶囊播完整的火花 / 对勾动画。

### 完成动画

收起态胶囊在计时结束时切换到 `data-mode="done"`：SVG 里的圆环做两轮扩散、六道火花沿径向飞出、对勾用 `stroke-dashoffset` 逐笔画出，标题延后 160ms 滑入。整套只在进入完成态时播一次，`key={finish.id}` 让连续几个计时器完成时各自重播；8 秒后收起态自动切回进度环或时钟，`prefers-reduced-motion` 下全部直接到位。

### 输入法与 Enter

中文输入法激活时，Enter 常被候选窗吞掉，`onKeyDown` 收不到。所以输入行左侧的 `+` 是一个真实的提交按钮，回车只是快捷键。代码里也检查了 `isComposing`，避免上屏候选词时误提交。

## 已知限制

- 仅主显示器顶部生效，不跟随多屏
- 展开时窗口会接管「面板 + 40/60px 边距」区域的鼠标，透明部分也会吞掉点击（离开 320ms 内）
- 开发模式下系统通知的发送方显示为 "Windows PowerShell"，打包安装后才显示 NotchHub
- 数据存于 WebView2 的 localStorage，清缓存会丢
- 安装包没有代码签名，首次运行 / 升级可能被 SmartScreen 拦一次；自动更新只校验 GitHub 给出的 SHA-256，不做签名验证
